The most relevant thing I have built

A browser power dialer on Telnyx SIP, written end to end.

You own the SIP edge and the media plane, so this is the one worth reading. Browser WebRTC client, a Cloudflare Worker as the whole API, a D1 database, Telnyx for SIP and PSTN. The browser gets a short-lived JWT instead of a permanent SIP password. Webhooks are Ed25519 signature-verified and idempotent. Caller ID rotates across four numbers with a daily cap per number. The queue holds 5,903 leads, deduplicated to zero on a normalised phone key.

The part I learned most from was the failures, each found by reading the call flow rather than guessing:

  • Every outbound call was rejected because the call-control application had no outbound voice profile attached. It looked like a balance problem. It was config.
  • Calls reached "connecting" and stopped because nothing ever answered the transferred leg in the browser, and the far-end audio had no element to play into. That setting is an answer option, not a client option, which is why it hid.
  • The messaging profile's webhook still pointed at the old app, so inbound SMS and delivery receipts were silently going elsewhere. Now I check every webhook on every profile when an app moves.
